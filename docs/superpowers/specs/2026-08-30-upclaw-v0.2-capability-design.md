# UpClaw v0.2.0 能力提升设计文档

日期：2026-08-30
状态：已批准（用户确认）

## 背景与目标

UpClaw v0.1.0 已开源（Apache-2.0），但存在「宣传与实不符」问题：
README 宣称 23 项渗透技能 + AI 驱动工作流，实际仅 4 个检测模块（headers/sensitive/sqli/xss），
且无任何 LLM API 调用。本设计通过**补齐检测能力**使工具名副其实，
保持既有核心优势（零第三方依赖、授权门禁、证据级反幻觉报告）。

明确**不在本次范围**：AI 工作流接线（需用户提供 API Key，且 doctor 已提示功能不可用）；
时间盲注（DoS 风险，延续现有红线）；真实密码爆破字典（避免滥用）。

## 架构

保持单文件结构，扩展 `AVAILABLE` 注册表（4 → 20+ 模块），统一接口：

```python
def _run_xxx(store: FindingStore, url: str, cfg: dict[str, Any]) -> None: ...
```

- `FindingStore.add(**kw)` 复用：title/severity/status/category/target/location/
  description/evidence/request/impact/remediation/references/cvss
- 辅助函数复用：`_get` / `_build` / `_extract_snippet` / `RateLimiter` / `parse_target` / `resolve` / `tcp_connect`
- 新模块遵循现有证据规范：内置载荷字典 + 基线对比（排除误报）+ 证据片段 + CVSS + OWASP 引用 + 修复建议

## 新增模块清单

### 信息收集（4）
| 模块 | 实现 |
|------|------|
| dns | 手写 DNS 报文（socket UDP），A/AAAA/MX/TXT/NS/SOA 记录枚举 |
| subdomain | 内置常见子域字典 + DNS 解析验证存活 |
| waf | 恶意载荷探测 + 拦截特征（403/拦截页/验证码）识别 |
| tls | ssl 握手，协议版本 / 证书有效期 / 自签名 / 链校验 |

### 漏洞验证（6）
| 模块 | 实现 |
|------|------|
| cmdi | 回显型 + 报错型命令注入（id / ;id 等 payload） |
| ssrf | URL 参数注入内网地址 + 响应差分检测 |
| xxe | DOCTYPE 外部实体注入 + 回显检测 |
| lfi | 路径遍历 payload（../../etc/passwd）特征匹配 |
| open-redirect | Location 头反射检测 |
| crlf | 响应头拆分（%0d%0a 注入）检测 |

### 暴力破解（3）
| 模块 | 实现 |
|------|------|
| dir | 内置 100+ 路径字典并发探测（含状态码分级） |
| backup | .bak/.zip/.tar/.sql/.old 等备份后缀探测 |
| fuzz | 常见参数名（debug/admin/test/cache）模糊探测 |

### Web 安全（4）
| 模块 | 实现 |
|------|------|
| cors | Origin 反射 + Access-Control-Allow-Credentials 检测 |
| cookie | Secure/HttpOnly/SameSite 逐项检查 |
| methods | OPTIONS 探测 TRACE/PUT/DELETE 等危险方法 |
| webdav | OPTIONS 检测 PUT/MOVE/PROPFIND 启用 |

### 保留现有（4）
headers / sensitive / sqli / xss
